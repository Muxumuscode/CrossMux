## 1. Size the TTF stream-prefix cache to the font's real tables
- **Upstream:** crosspoint-reader [#4583](https://github.com/crosspoint-reader/crosspoint-reader/pull/4583) (`d1fda4e6`)
- **What it does:** A streamed TTF/OTF face caches its first 1 MB in PSRAM. The patch reads the sfnt table directory first and allocates only the lookup tables before `glyf` (still capped at 1 MB). That is usually 70–750 KB; ChareInk needs about 68 KB.
- **Why it fits CrossMux:** CrossMux does exactly this today in `lib/ScalableFont/HalScalableFont.cpp:656` (`PrefixLimit = 1024 * 1024`, `prefix = min(size, PrefixLimit)`). With a regular/bold/italic family loaded, the T5 can tie up 3–4 MB of its 8 MB PSRAM.
- **Cost:** about +1 KB flash. On S3/T5 it frees roughly 0.3–0.9 MB of PSRAM per loaded face. No effect on C3: that path is PSRAM-only.
- **Difficulty:** easy–moderate. Upstream changed `src/SdCardFontSystem.cpp`; CrossMux has a different font stack, so this is a re-implementation in `HalScalableFont.cpp` (parse the table directory, then size `streamPrefix_`). Fall back to the current 1 MB for TTC files or unusual layouts.
- **Conflicts:** none with the T5 port, the SDK branch or the Dashboard theme.

## 2. Smoother reading on PSRAM devices (CrossInk bundle)
- **Upstream:** CrossInk `development`: [037476d6](https://github.com/uxjulia/CrossInk/commit/037476d632faec66da9e6f6c8448608066935268) (prepare the next chapter while reading), [b79c0d0a](https://github.com/uxjulia/CrossInk/commit/b79c0d0a096331d85cff33b2223c4a219e5bb6cd) (finish incremental indexing while idle), [0c6826ee](https://github.com/uxjulia/CrossInk/commit/0c6826eedb6c9e13dbc05d748911a5ac4ab41ce1) (return to the page sooner after layout changes), [47a12b1e](https://github.com/uxjulia/CrossInk/commit/47a12b1e536376078a73fbc67de9af52677ba078) (page turns stay responsive during indexing)
- **What it does:** On readers with PSRAM, idle time is used to finish laying out the current chapter and the first pages of the next one. Chapter turns stop stalling, and after a font change the reader returns to your page before indexing finishes.
- **Why it fits CrossMux:** All four are gated on `hasIndexingPsram` (`ESP.getPsramSize() > 0`), so they switch on automatically for the T5. The T5's 540×960 page is costly to index, so it gains the most.
- **Cost:** about +4–6 KB flash. Prefetch buffers are temporary and come from PSRAM; internal RAM is unchanged. The C3 path is unchanged.
- **Difficulty:** easy through the next CrossInk release merge. Cherry-picking them early is **hard**: they depend on each other and each one bumps the `section.bin` version. Touches `src/activities/reader/EpubReaderActivity.{h,cpp}`, `src/activities/ActivityManager.{h,cpp}`, `lib/Epub/Epub/Section.{h,cpp}`, `src/main.cpp`, and in `0c6826ee` also `lib/hal/HalDisplay.{h,cpp}` and `lib/GfxRenderer`.
- **Conflicts:** small ones, in the CrossMux additions to `main.cpp` and `ActivityManager.cpp`. `0c6826ee` refreshes the status bar without redrawing the page "on supported displays". Check that the T5 panel reports that it does *not* support this, or test the partial refresh on the T5.

## 4. Don't hyphenate headings
- **Upstream:** crosspoint-reader [#4442](https://github.com/crosspoint-reader/crosspoint-reader/pull/4442) (`4b6fdece`)
- **What it does:** Turns off hyphenation for heading blocks, so chapter titles no longer break across lines as "Chap-/ter".
- **Why it fits CrossMux:** A typography fix that is in scope. CrossMux still passes the global `hyphenationEnabled` to every `ParsedText`, headings included (`lib/Epub/Epub/parsers/ChapterHtmlSlimParser.cpp:1368`). CrossInk has not taken this change.
- **Cost:** under 0.5 KB flash, no RAM.
- **Difficulty:** easy–moderate. Turn hyphenation off when the block is `h1`–`h6`, add a setter in `lib/Epub/Epub/ParsedText.h`, and bump `SECTION_FILE_VERSION` in `lib/Epub/Epub/Section.cpp` (documented in `docs/file-formats.md`). The bump will collide with the next CrossInk merge, so either take it right after that merge or expect a one-line conflict.
- **Conflicts:** none with T5, the SDK or Dashboard.

## 7. Bound `readString()` so a failing SD card can't abort boot
- **Upstream:** crosspoint-aurora [e7b2c122](https://github.com/jetaudio/crosspoint-aurora/commit/e7b2c122d5cebc0fd777e5fb421db5742aa4d768)
- **What it does:** If the card stops answering mid-read it returns `0xFF` bytes. The length prefix then decodes as about 4 GB, and `resize()` aborts the firmware. The patch rejects any length longer than what is left of the file.
- **Why it fits CrossMux:** CrossMux's EPUB path already uses the bounded `tryReadString`. However, the unbounded `readString(FsFile&)` in `lib/Serialization/Serialization.h:62` is still used to load `RecentBooksStore`, `CrossPointState` and `WifiCredentialStore` at boot. One corrupt file or flaky card there means a crash loop instead of empty defaults.
- **Cost:** under 100 B flash, no RAM.
- **Difficulty:** easy. One function in `lib/Serialization/Serialization.h`.
- **Conflicts:** none, and it matches what CrossPoint already does in `tryReadString`.
